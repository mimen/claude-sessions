Goal

Turn the CCS productivity sidebar from a session list into a triage queue. Scan overall state at a glance (open / closed / complete / archived, plus what is suggested to become complete or archived) and blow through sessions: mark done, close to reclaim RAM, reopen, archive, hand off.

The organising principle: closing is a RAM decision, not a work decision. It should feel like closing a browser tab and must never imply losing the session. Complete and archive are work decisions and belong on a separate axis.

What we found

Enrichment v40 already computes the triage verdict

Catalogue v40 shipped 2026-07-26 (229d2e2) explicitly to make dispositions sortable. Its commit message states the problem it solved: "47.5% of 468 sessions said continue, which sorts nothing."

  • summary split into state (where it stands now) + history
  • outstanding split into next (one imperative action) + remaining
  • reason is conditional: required for archive/handoff/junk, required empty otherwise
  • junk implies archive; cwd_correct nullable (NULL = never asked)
  • Enrichment reads measured evidence (cwd exists, branch exists, successor count), not just the transcript

The sidebar currently reads the pre-v40 fields (summary, outstanding) and ignores the recommendation entirely.

Diagnosis

Three independent axes are collapsed into one section field:

AxisValuesMeaning
Livenessopen / closedRAM. Reversible, cheap, not a judgment
Dispositionactive / complete / archivedWork state. A real decision
Suggestioncomplete / archive / continue / handoffWhat enrichment thinks should happen

Today recent (liveness) sits alongside needs-you (status) as if they were the same kind of thing. That conflation is why closing feels like losing: a closed session drops to the bottom of one flat ordering and is then truncated.

Confirmed decisions

1. Triage lives as inline chips plus a Triage scope. Every row carries its suggestion as a chip (✓complete / ▪archive / ⇢handoff) accepted or dismissed in one click. The existing scope selector gains a Triage option filtering to un-acted suggestions. Normal browsing is unchanged; no session ever appears in two groups.
2. Infinite scroll, no caps. Closed and archived groups page in as you scroll (~50 at a time). Requires paging the snapshot API and virtualised rows so a thousand one-liners stay smooth.
3. Row density is a first-class concept, not a per-section hack. Three tiers, driven by a density field on the projected row:
  • full box — live sessions (open, costs RAM)
  • one-line — closed sessions whose work is still active
  • one-line in a collapsed dropdown — complete and archived
4. The muted/non-bold treatment moves to idle-but-open. It is a good "does this need me" signal and is currently spent on closed sessions, where structural lightness does the job better.
5. COMPLETE and ARCHIVED are sticky bars pinned to the bottom edge, not sections below the scroll. An infinite list has no bottom, so anything placed after it in document order is unreachable. Their collapsed bars stay fixed at the bottom of the sidebar and are one click away from any scroll position. Expanding one turns it into the scrolling list (accordion), so exactly one unbounded list is ever live and "scroll to the end" always terminates. Side effect: the two counts are permanently visible, which is itself the overall-state readout.

Implementation approach

  1. Projection (src/sidebar/projection.ts): read v40 fields (state, next, remaining, history) with fallback to legacy summary/outstanding; add suggestion and density to the row union. Rows stay a discriminated union per house style.
  2. Shared reader (src/catalogue/enrichment.ts): extend to the v40 columns so the sidebar and TUI keep reading one source.
  3. Snapshot + server: drop RECENT_LIMIT, add cursor paging to GET /api/snapshot.
  4. Web: three row components by density; collapsible COMPLETE/ARCHIVED sections; suggestion chips; Triage scope; scroll paging.
  5. Actions: chips call the existing POST /api/session/lifecycle (complete / archive / uncomplete / unarchive). No new mutation path, so ADR-0068's catalogue boundary is respected.

Open questions

All resolved 2026-07-27. Kept here as the record of what was asked and decided.

6. handoff is display-only. The chip shows the verdict but is not actionable from the sidebar: performing a handoff is work that happens inside the session, not a lifecycle flag flipped from a list. Only complete and archive get accept buttons, and both map to lifecycle verbs that already exist.
7. Dismissal gets a catalogue column. Without one a dismissed chip returns on the next enrichment sweep. The column records which verb was dismissed, not merely that something was: dismissing archive must not suppress a later complete, because enrichment changing its mind is new information rather than the same suggestion repeating.
8. Junk stays individual clicks. The 71 junk rows surface their archive suggestion like any other row. No bulk action: junk is enrichment's inference, and 71 sessions disappearing on one click is a lot of trust to place in it.
9. Last-known cmux status is not persisted. It dies with the workspace and stays dead. Enrichment's state and next already answer the same question durably and more usefully, so recording the pill would add a write per poll for a strictly weaker signal.

Non-goals

  • No deletion. Closed, complete, and archived sessions all stay searchable and reopenable.
  • No change to how enrichment computes anything. This consumes v40; it does not modify it.
  • No new global cmux setting. The sidebar is a web page and owns its own view state.
