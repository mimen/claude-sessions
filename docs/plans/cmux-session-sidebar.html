CCS × cmux

Productivity sidebar

A fast work queue answering: what is running, what needs me, and what should I resume?

V1 complete V2 built and running Dock placement is a manual step

Product decisions

T3 is visual reference only. Use its dense rows, model/provider icon treatment, hover surface, selected surface, and status hierarchy.
cmux supplies active work. Presence already means live. Surface cmux’s actual claude_code status, such as Running, rather than adding a redundant liveness badge.
CCS supplies resume. Its useful job here is showing a short shelf of recent resumable sessions and performing managed resume. Cost, lineage, fleet structure, and catalogue metadata stay out.

Sections

  1. Needs you: Claude is waiting for input, permission, review, or another user action.
  2. Working: active Claude sessions whose cmux Claude status says they are running.
  3. Ready: live Claude workspaces sitting at the prompt, available to continue.
  4. Recent sessions: a collapsed, capped CCS shelf for sessions not currently in cmux. Click resumes through CCS.
  5. Other workspaces: compact non-Claude cmux tools such as the CCS TUI.

  • Bottom right: short model name plus the provider’s own logo, then time since the last message. Examples: Sol, Fable, Opus, and Sonnet.
  • Click focuses the live workspace. Hover changes the surface and may reveal one contextual action.

Logos are the vendors’ own, unaltered — only sized. The OpenAI mark follows the theme because that is how it is published; the Claude mark keeps #D97757 in both. The model label sits in muted ink so one chip carries one color.

Controls

  • Up/down and Enter for fast keyboard navigation.
  • One-click focus for live rows.
  • One-click managed resume for Recent sessions.
  • Optional Clear action for a dismissed attention item.
  • No inline administration menu. Rename, archive, lineage, and full catalogue browsing remain in the CCS TUI.

Remove

  • Cost and token usage.
  • Lineage, parent/child structure, seats, and fleet metadata.
  • Redundant cmux liveness indicators.
  • Progress percentages.
  • Port count, tab count, remote-server icons, PR chips, and dirty-branch clutter.
  • A full detached-session catalogue.

Implementation shape

cmux Dock browser → CCS-owned React host → cmux workspace/status data plus a small CCS Recent-session query. No T3 runtime dependency and no browser access to CCS databases.

Built

  1. Pure projection in src/sidebar/projection.ts: sections, row anatomy, model identity, cmux glyph stripping.
  2. Adapters for cmux’s claude_code status pill, git worktrees, and project favicons.
  3. One interface in snapshot.ts: snapshot(), open(), faviconFor().
  4. Loopback host on 127.0.0.1:8787, wired as ccs sidebar serve|url.
  5. React app with sections, hover, selected surface, filter, and session-stable keyboard navigation.
  6. Click routing: focus when live, CCS-managed resume when not, fail closed when cmux is unreadable.
  7. Docs at src/sidebar/README.md.

Review fixes landed

A primary review found six defects; three implementer agents fixed them in parallel, partitioned by file.

  • Duplicate spawn — a second click during the window before cmux binds a resumed surface could spawn the session twice. Now guarded by a per-session single flight plus a recently-resumed window.
  • Launcher fail-open — an unreadable launcher config silently resumed a GPT-origin session on plain claude. Now fails closed.
  • Favicon — symlink escape, a replace-after-check window, and same-origin SVG execution. Symlinks refused, the file re-opened with O_NOFOLLOW and identity-matched, SVG excluded, nosniff and a locked-down CSP added.
  • Trust boundary — --host silently exposed the LAN and no endpoint validated Host. Non-loopback binds are now refused outright and every request checks Host.
  • Status truthfulness — statuses were targeted by mutable numeric refs, and an unreadable status demoted a running session to Ready. Now keyed on the stable workspace UUID, with an unread status distinguished from an absent one.
  • Polling — neither single-flight nor ordered. Now one flight, with late responses unable to overwrite newer state.

Degraded-index finding

Found while verifying: the sidebar returned HTTP 500 and rendered nothing, because the shared session index had been migrated to schema 11 while this branch supports 10. The index only supplies model identity and the resume shelf — cmux alone already knows what is running — so failing the whole snapshot was wrong. It now degrades to live rows and says which half is missing.

Separate, wider issue: feat/swap-harness declares schema 11 and migrated the shared database; master and every other branch declare 10 and can no longer read it. That affects ccs ls and the TUI too, not just the sidebar. Milad's call to resolve.

Design pass in flight

Standard shadcn theme, zinc base, in oklch. Pulled from shadcn's own registry rather than approximated, and stored at docs/shadcn-zinc-reference.css.
Theme follows the system automatically. cmux's own themes are set to inherit, so it already tracks macOS; the Dock browser gets the same signal through prefers-color-scheme. Auto therefore matches cmux with no cmux-specific integration.
Worktree name is hidden in the row. Only the project shows. The worktree stays in the projection so the hover preview card can use it.
Model colours come from CCS. modelOf now takes its colour from familyOf in src/tui/format.ts instead of keeping a copy, so the sidebar and the TUI cannot drift. A test locks them together.
  • Tailwind v4 with a CSS-first @theme, compiled into the Bun bundle so ccs sidebar serve stays one self-contained command.
  • kibo-ui Status for the cmux status pill.
  • coss preview-card for row hover detail — it is a hover card, so the row stays dense and path, branch, and worktree live in the popup.
  • @lobehub/icons-static-svg (MIT, 903 official brand SVGs) for model marks, inlined into the bundle.

Remaining

  • The host runs detached but is not installed to start on login; that needs a LaunchAgent.
  • Live focus and resume were not exercised end to end, to avoid moving the active workspace unasked.
  • V1 remains installed and unchanged. No Dock configuration file was written; the Dock surface was added with a single command.
