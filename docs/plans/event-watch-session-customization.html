Event Watch session customization

Status: implementation authorized. V1 is in progress: role colors, CMUX title templates, static core names, humanized worker titles, and lifecycle-only pills. Event Watch behavior remains unchanged.

Artifact: /Users/mimen/Programming/Repos/claude-sessions/docs/plans/event-watch-session-customization.html

Goal

Give Event Watch sessions an immediately legible CMUX presence—role-aware tab names and colors, concise descriptions, useful lifecycle/state pills, and predictable repaint behavior—without duplicating Event-domain facts in CCS, changing worker loop policy, or introducing a scheduler.

Confirmed current state

  • Live Event Watch package has no hooks. ccs hooks explain reports no cmux-paint or start hook at cluster, coordinator, scout, or event-worker scope.
  • The current package declares two loop cores (coordinator, scout) and one manual freeform fleet role (event-worker).
  • CCS paints a tab on SessionStart, Stop, resume, and selector-based ccs sync-tabs. A sweep is required because another actor can mutate an idle session’s row.
  • cmux-paint is most-specific wins. It can override title, description, color, lifecycle/state pill, epic pill, and alert pill. A role color = "#RRGGBB" is also the shared TUI/CMUX accent when no paint color overrides it.
  • PR Watch’s frozen reference uses role-local cmux-paint.json primarily for concise core titles such as pr-watch • control, plus start actions (arm / drain-inbox), spawn locations, and stop-context guidance. It does not provide Event Watch assets to copy wholesale.
  • Event Watch’s worker behavior authority remains vault-canonical skills and the Event Watch engine. This package remains an orchestration/display layer.

Confirmed design: model selection becomes a generic role capability. A role declares a full canonical model ID in role.toml; CCS resolves that model to native claude or claude-gpt at birth and resume. Role config names what; CCS owns how. Unsupported or unresolvable models fail before launch—never silently fall back. Policy takes effect on future birth/resume only; it does not switch a running embodiment or rewrite historical model records.

Role model launch-policy architecture

role.toml
  model = "claude-opus-4-8" | "gpt-5.6-terra" | "gpt-5.6-sol"
        ↓ strict closed CCS compiler (before UUID/catalogue reservation)
  native Claude: claude --model claude-opus-4-8 ...
  GPT harness:   claude-gpt --model gpt-5.6-terra[1m] ...
        ↓
  provenance recorded for observability only

resume
  transcript/index model history → existing compatible launcher resolver
  no role-model override; no implicit backend/model switch
  • Role config authors only the canonical model. Provider, launcher binary, and compiled gateway model derive from a closed CCS registry.
  • Model-bearing roles reject --via and unsupported/malformed/alias/suffixed model strings before any reservation or launch.
  • Policy-less roles preserve today’s default birth and manual --via behavior.
  • The launcher used at birth is recorded as session provenance but is not resume policy; history-compatible replay remains authoritative.

State and pill contract

Tab-title finding: the TUI row label and CMUX workspace title use separate render paths. The current CMUX worker fallback can expose the raw identity key when no custom title exists. Static role-level cmux-paint.json titles solve core names but would make every worker identical. V1 therefore needs a narrow renderer/template capability that derives a worker title from its identity work-reference.

V1 pills: use only CCS lifecycle pills—parked, done, archived—and clear stale entries through existing pushRenderOps. Do not claim “planning,” “outreach,” “ticketed,” or other Event Watch stages until the vault/engine exposes one authoritative, machine-readable source.

V2 (explicitly deferred): add an Event Watch board composer or a narrow adapter that reads one authoritative event-state source and emits a state pill plus an alert pill. This is display-only; it must not become a second Event Watch state store.

Open decisions

  1. Palette decided: a coherent event-world family: coordinator #7057C7 deep violet, scout #20B8C8 electric cyan, and workers #D28A3A warm amber. Lifecycle/alert pills—not tab color—carry urgency.
  2. Worker CMUX title source: V1 should render the existing humanized identity work-reference rather than the raw key. The unresolved implementation choice is a generic template mechanism versus a narrowly scoped renderer fallback. A vault-authoritative event title requires an explicit display mapping or lookup and remains deferred.
  3. Status scope: lifecycle-only now (recommended) versus an Event Watch state adapter in the first pass.

Implementation and verification plan

  1. Design and implement a role launch-policy contract in CCS for pinned native versus claude-gpt models. It must apply to new sessions and resume, and must fail closed rather than silently using the default launcher.
  2. Add valid role colors, launch policy, and cmux-paint.json files in the private config package; document why the worker title remains computed rather than static.
  3. Add isolated contract tests for paint ownership, role color validity, static core titles, absence of a static worker title, and exact launch-policy resolution.
  4. Run package tests plus ccs hooks lint under isolated roots. Review the resolved hook output before touching live sessions.
  5. Commit/push the config-only package change. Do not resume or wake sessions.
  6. Perform an explicit, bounded live ccs sync-tabs --cluster=event-watch after recording the pre-state. Verify only intended titles/colors/pills changed; no session launch, inbox, registry, or vault mutation.
  7. Rollback by removing the three paint files and colors, then run the same selector-based repaint to restore renderer defaults. No session deletion or transcript manipulation.

Constraints and non-goals

  • Do not copy PR Watch’s old engine, filesystem inbox, scheduler, lifecycle policy, or PR-specific stop context.
  • Do not alter Event Watch vault skills, engine scripts, registry, event folders, or Airtable data.
  • Do not wake, resume, loop, spawn, or bump workers as part of visual customization.
  • Do not store event names, stages, dates, or Airtable IDs in the Event Worker identity schema.
  • Keep raw identity keys available in CCS detail, copy, CLI, and JSON surfaces; they are not tab labels.
