Implementation plan · read only

Make the sidebar fast by removing work, not hiding rows.

The product remains intact: every ordinary session loads, liveness remains exact, resume fails closed, and CCS continues to own session lifecycle. The architecture changes underneath it so read traffic cannot acquire write locks, unchanged data is not recomputed or retransmitted, and session actions stop blocking the server.

Status: implementation complete and verified. The full CCS architecture wave landed and passed its final quiet soak. Measurements rejected SSE and justified the narrower typed cmux focus bridge. Independent primary and Fable reviews closed the blocking findings before delivery.

The decision

Three deep modules replace one overloaded request path.

1

CatalogueReader

A query-only adapter selects only sidebar fields. It cannot migrate, materialize, run DDL, stamp schema versions, or acquire a reserved write lock.

2

SidebarReadCache

SQLite data_version provides exact invalidation for durable projections. A generation tuple produces ETags so unchanged polls return 304 with no JSON body.

3

SessionActionCoordinator

One fresh liveness read, per-session single-flight, asynchronous cmux processes, typed results, and cosmetic paint after the response.

Read lane

Query-only durable data

Catalogue and index facts are read through narrow adapters and cached by exact source revision.

  • No migrations in GET requests
  • No SELECT *
  • No per-row identity N+1
  • No duplicate enrichment pass
→
Projection lane

Pure sidebar projection

The existing product logic remains a pure join of durable facts, live workspace facts, scope, and shelf state.

  • Wire shape preserved initially
  • All rows still load
  • Last good rows survive degraded reads
  • ETag represents source generations
→
Action lane

Async authoritative actions

Server actions recheck liveness, preserve fail-closed resume, and never block unrelated HTTP traffic on synchronous subprocesses.

  • One Bridge per action
  • No raw SQL mutations
  • Paint is best-effort and self-healing
  • Structured error envelope

Product behavior that does not change

  • All non-auxiliary rows load immediately.
  • Completed and archived remain normal shelfable sections.
  • Live and closed rows retain current actions and summaries.
  • The server remains authoritative about focus versus resume.
  • A stale client can never trigger a duplicate resume.

Platform guarantees that become stronger

  • Read requests cannot contend as catalogue writers.
  • Unreadable remains distinct from absent.
  • Every mutation crosses the command seam from ADR-0068.
  • Every network and liveness failure has a stable error kind.
  • Performance regressions gain executable budgets.

Implementation sequence

Eight independently shippable slices.

Behavior changes and file movement do not share a commit. Each slice has one measurable claim, one rollback, and a regression test at the seam where the bug occurred.

0

Freeze behavior and measure the real flow

Add observability and characterization before replacing any implementation.

  • Record snapshot phase timings: bridge, catalogue, index, status, projection, serialization.
  • Log structured slow requests above 100ms and classify liveness failures by cause.
  • Add the live-focus benchmark, writer-lock contention harness, response-size measurement, and a 60-second idle profile.
  • Capture normalized snapshots for active, triage, completed, archived, unreadable catalogue, and unreadable index.
Exit gateExisting behavior is reproducible and the writer-locking snapshot path fails the new contention and latency tests.
1

Remove catalogue writes from the read path

Add src/sidebar/catalogue-read.ts, mirroring the version-tolerant shape of index-read.ts.

type CatalogueReadError = | { kind: "missing" } | { kind: "unreadable"; message: string } | { kind: "unsupported-schema"; message: string }; function readSidebarCatalogue(path: string): Result<SidebarCatalogueFacts, CatalogueReadError>;
  • Open SQLite with { readonly: true } and PRAGMA query_only = ON.
  • Probe table and column presence. Detect enrichment_declined by presence, never by user_version.
  • Select only sidebar lifecycle, identity, membership, and enrichment fields with one bounded join.
  • No WAL setup, migration, materialization, filesystem migration, schema stamping, or role-config loading.
  • Preserve current degradation: missing or unreadable catalogue keeps live rows rather than blanking the sidebar.
Exit gateA held writer lock cannot delay snapshot generation beyond 120ms, and snapshot reads do not modify the database, WAL, or schema version.
2

Cache exact durable projections and return 304 for unchanged state

Introduce SidebarReadCache keyed by catalogue and index data_version, following the existing catalogue authority pattern.

interface SidebarReadCache { read(): Result<SidebarDurableFacts, SidebarReadError>; revision(): SidebarDurableRevision; invalidate(): void; }
  • Cache durable facts, not scope-specific HTTP responses.
  • Build an ETag from durable revisions plus live/status cache generations and request scope.
  • Honor If-None-Match with 304 and no body.
  • Keep the one-second poll initially so freshness behavior does not change.
  • Back off consecutive transport failures and refresh immediately on visibility return or successful action.
Exit gateUnchanged polling responds under 10ms with 304; a write from a second connection invalidates on the next request; every source change yields 200 with the expected snapshot.
3

Deepen the action path and remove synchronous subprocesses

Extract SessionActionCoordinator from snapshot.ts. The server route becomes transport only.

type OpenResult = | { kind: "focused" } | { kind: "resumed"; workspaceRef: string } | { kind: "already-open" } | { kind: "not-indexed" } | { kind: "liveness-unreadable"; reason: LivenessError } | { kind: "failed"; error: ActionError }; interface SessionActionCoordinator { open(sessionId: string): Promise<OpenResult>; }
  • Read one fresh Bridge per action and pass its concrete location into focus. Never rebuild liveness synchronously.
  • Replace execFileSync and Bun.spawnSync in sidebar action flows with async process adapters.
  • Retain per-session single-flight and make a repeat click focus the actual workspace rather than returning a silent recent-success no-op.
  • Return after the workspace exists. Queue tab paint afterward; SessionStart and the selector-driven sweep remain the self-healing guarantee from ADR-0056.
  • Pass the loaded row or read-only facts into paint so it cannot reopen the catalogue as a writer.
Exit gateLive focus p95 is below 150ms; resume acknowledgment p95 is below 700ms; snapshot traffic continues responding while an action is in flight.
4

Put mutations and failures through their declared seams

Close correctness gaps exposed by the performance work.

  • Replace raw sidebar SQL with sanctioned command-layer operations for lifecycle, recommendation decline, and index-gated session adoption.
  • Preserve atomic identity mirroring and phantom-row protection from existing commands.
  • Return { code, message, retryable } from server failures and log every catch before responding.
  • Add typed browser transport with explicit snapshot and action deadlines. Never render raw WebKit TypeError text.
  • Keep absent, unreadable, stale, denied, timed out, and not found distinct.
Exit gateThe mutation-boundary test catches direct sidebar SQL; every transport error has a behavior-level test; no persistent "Load failed" toast exists.
5

Consolidate duplicated concepts behind shared interfaces

After latency and correctness are stable, remove implementations that can drift again.

  • One StoredEnrichment shape and one reader. Remove conflicting nullability and recommendation fallbacks.
  • One recommendation-disagreement function shared by CLI triage and sidebar suggestions.
  • One generic warm-cache implementation shared by status, workspace state, and notifications, including the synchronous-throw single-flight fix.
  • Split pure projection into live-row construction, indexed-row construction, and section selection while keeping projectSidebar as the composed interface.
  • Extract web snapshot transport and action transport from App.tsx; presentation remains in React.
Exit gateProjection, shelf-storage, triage, and degradation fixtures are equivalent after normalization.
6

Complete the physical module split and enforce it

Finish ADR-0068 only after behavior is protected, with file movement isolated from logic changes.

  • db-schema.ts: schema readiness and migrations.
  • db-queries.ts: unrestricted query-only functions.
  • db-mutations.ts: command-layer-only writes.
  • Strengthen the import test so raw database construction and mutation SQL outside sanctioned modules fail CI.
  • Run lint:circular after every move and keep orchestration importing data, never the reverse.
  • Update domain context, system-unit docs, and the sidebar README with the new read, projection, and action vocabulary.
Exit gateFull tests, typechecks, circular-dependency lint, and snapshot benchmarks are unchanged or better after the mechanical split.
7

Soak, remove fallbacks, then decide whether more machinery is justified

Run the installed sidebar against the real fleet before adding another transport.

  • Thirty-minute idle soak and a fifty-click focus sample with the live sidebar open.
  • Exercise closed resume, repeated clicks, lifecycle changes, writer contention, missing index, missing catalogue, cmux socket failure, and server restart.
  • Remove temporary read-path flags and the old snapshot reader that calls openCatalogue() after parity is proven.
  • Consider SSE only if 304 polling still exceeds idle CPU or freshness budgets.
  • Consider a cmux web action bridge only if optimized focus remains above 150ms.
Exit gateNo false liveness-unreadable state, raw transport error, duplicate resume, blank sidebar, or performance regression across the soak.

Rollout and rollback

No phase needs the next phase to be safe.

Rollout

  • Build each behavioral slice in its own commit and keep mechanical moves separate.
  • Use temporary flags only for the read adapter and ETag path.
  • Client and server stay version-tolerant: missing ETag support falls back to normal 200 polling.
  • Ship the read path before actions so the largest lock hazard disappears first.
  • Implementation starts in fresh worktrees that explicitly layer sidebar commit ee0f57e over fresh origin/master.

Rollback

  • Disable the reader flag during the short parity window.
  • Disable ETag generation without changing the snapshot body.
  • Revert action commits independently; result unions remain compatible until soak completes.
  • Restore synchronous paint without touching resume planning if needed.
  • No first-wave database schema migration is required.
Fallback lifetime is bounded. The legacy writer-opening read path is removed after the soak. It does not remain as permanent dual architecture.

Excluded until evidence changes

Useful ideas that are not yet no-brainers.

Rejected

Generic HTML-to-cmux dispatch

The interpreted dispatch is a raw method passthrough, while a .url custom-sidebar configuration can point its WebView at any HTTP or HTTPS page, including remote content.

Conditional

Typed local focus bridge

Consider only after optimized focus remains above 150ms. Local document or exact loopback origin, main frame only, dispatch-time URL verification, fixed focus verb, no redirects, no remote source.

Conditional

SSE or WebSockets

ETag polling is simpler and preserves current lifecycle behavior. Add push only if post-fix idle measurements justify it.

Conditional

Worker process or thread

First remove writer locks and synchronous subprocesses. Process isolation needs a measured remaining stall.

Rejected

Pagination or row removal

It overturns the deliberate full-list decision and treats a backend defect as a visibility feature.

Rejected

Cached liveness for resume

Display may use cached live facts, but spawn and resume require a fresh readable Bridge under ADR-0054.

Rejected

Persistent raw cmux socket client

It duplicates CLI authentication, normalization, and wire compatibility for little gain after async focus.

Rejected

Merge catalogue and index

Durable identity state and rebuildable transcript facts remain separate by the platform model.

Shipped record

The architecture changed as planned. The evidence changed one platform decision.

CCS shipped the query-only read lane, exact durable invalidation, serialized response cache, strong ETags, stale-while-revalidate liveness, asynchronous actions, command-only mutations, typed failures, the physical catalogue split, bounded caches, hard subprocess termination, and single-flight resume. The final code of record is 5d9196f2f72c5cf03eda84621ba35f4a468b10f5.

Measured outcome

  • The isolated unchanged-response p95 is 2.908ms with HTTP 304 and zero body bytes.
  • The isolated changed-visible p95 is 0.191ms.
  • The 30-minute live soak completed 1,800 polls at p50 0.461ms and p95 37.021ms, with zero failures and zero degraded snapshots.
  • Real writer contention completed in 91.847ms, below the 120ms contract.
  • Eight simultaneous live opens produced one resume, seven focused followers, and exactly one workspace.

Evidence-gated cmux follow-through

  • Optimized HTTP focus still missed the 150ms gate, so the conditional typed bridge was reopened.
  • cmux shipped one fixed rail-only workspace-focus verb, available only to local files and exact literal-loopback origins.
  • Fifty live native focuses completed at p50 4ms and p95 6ms with zero HTTP fallback.
  • Final review also moved custom-sidebar resolution and .url parsing off the main thread, made exact-case lookup independent of directory size, rejected non-regular web source files without blocking, bounded HTML validation, isolated test observation state, and pinned exact oversized-file diagnostics.
  • All review threads were resolved; Cursor and Socket checks passed, while unavailable or quota-limited bots were recorded rather than treated as code failures.
  • The final cmux code of record is a3a5541cb5614821bfd47aa375d5c2a967d3fe7e.
