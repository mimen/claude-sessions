The decision

Build this inside CCS

CCS is the Claude Sessions CLI and catalogue. It already understands launchers, models, transcripts, and notional model cost.

Recommended shape: add a typed provider telemetry layer under src/usage/, expose it through ccs usage, and let each provider adapter report the strongest evidence it can obtain, without flattening quotas of different kinds into a single percentage.

The utility joins two systems that exist separately today. CodexBar, the external helper this plan shells out to, can inspect live provider allowances and reset windows. CCS cost accounting reconstructs exact transcript token use and API-equivalent spend. Neither gives these five providers one source-aware view or answers the cross-provider reset question.

The product is an availability instrument, not primarily a billing dashboard. Its default sort is “what runs out next,” followed by “what expires unused,” then spend and historical burn.

Evidence contract

Never flatten uncertainty

A precise-looking number without provenance is worse than an explicit unknown.

Every metric carries a source class, observation time, scope, and exactness flag. Supported APIs can lead the UI while useful private or inferred values remain visibly qualified.

Official APIDocumented endpoint and supported authentication.
Provider headerLive capacity attached to a real request.
Official UI or CLIAuthoritative product surface, not a stable external API.
Observed privateReverse-engineered client endpoint, explicitly experimental.
Local estimateTranscript burn or forecast, never provider truth.

  scope: "account" | "organization" | "project" | "key" | "model" | "machine"
  window: "minute" | "five_hour" | "daily" | "weekly" | "monthly" | null
  used: number | null
  limit: number | null
  remaining: number | null
  resetsAt: string | null
  expiresAt: string | null
  observedAt: string
  source: "official_api" | "provider_header" | "official_ui" | "official_cli" | "observed_private" | "local_estimate"
  exact: boolean
}

Codex reset ledger

Banked is not “next reset”

Codex state deserves a dedicated model rather than generic credits.

CodexBar already exposes the reset-credit inventory, including lifecycle state, grant time, expiry, and separate five-hour and weekly windows. A banked full reset renews both windows and moves the weekly anchor, so redeeming it is a scheduling decision.

CodexBar for subscription-shaped providers

Shell out to its JSON CLI for Codex, Anthropic, Grok, and OpenCode Go where it already handles auth, account selection, pace, and reset lifecycle.

  • Repair or bypass only the provider adapters that fail.
  • Record helper version and source confidence.
  • One provider failure must not collapse the command.

Direct API for Venice

Use Venice's supported usage, balance, and rate-limit APIs because they expose stronger structured data than a helper abstraction.

  • Private endpoints remain experimental fallbacks.
  • Point-in-time output needs no persistent cache.
  • No generic provider framework is required beyond these five adapters.

Tradeoffs

Commitments the implementation should hold

Snapshot first, history second

Ship a reliable on-demand snapshot before a daemon, cloud store, or alerts.

Entitlements, not model IDs

Deduplicate routes by the account or subscription they consume.

Unknown beats fake precision

Never estimate consumer allowance from tokens. Show burn beside an explicit unknown.

No secrets in snapshots

Return account labels and auth health, never tokens, cookies, or management keys.

Gateway aggregation remains disabled. Version one reads the five providers' own usage or credit surfaces and does not add a second traffic-accounting system.

Locked scope

Version one stays narrow at the surface

  1. Providers: Codex, Anthropic, Grok, OpenCode Go, and Venice only. Other reachable models and API keys are outside version one.
  2. Grok accounting: consumer or team OIDC allowance and Extra Usage Credits only. Do not build xAI API billing support.
  3. Delivery: ship ccs usage plus a stable JSON contract. The CCS sidebar follows only after real provider output proves the schema.
  4. Persistence: point-in-time only. Version one stores no usage history and introduces no Convex or local-cache dependency.
  5. Gateway statistics: leave CLIProxyAPI aggregation disabled.
