Goal

A cluster is a fleet with a shape — roles, a coordinator, workers per unit of work — and the sidebar currently shows it as unrelated rows scattered through a flat list. The aim is an optional Clusters toggle that lifts cluster sessions into their own group at the top, makes the cluster's shape legible, and lets it be managed as a unit: which workers are open, which are closed, which slots exist but are not running.

The memory point is the sharp end. Eleven event-workers cannot all be open at once, and now that closed sessions are first-class the sidebar can show a cluster's full roster while only a couple of its members cost anything.

How clusters actually work

A session joins a cluster through catalogue.identity_key. The identity is the durable thing; sessions come and go beneath it.

The constraint on colours

cmux can set a workspace colour (workspace-action --action set-color) but neither tree --json nor list-workspaces reports it — verified: the workspace fields are active, description, index, panes, pinned, ref, selected, title, with no colour among them. The sidebar cannot mirror cmux's colours. Any colour here has to be the sidebar's own, which is arguably better: derived from the cluster name, it stays consistent whether or not a workspace is open, and a closed session keeps its colour where a mirrored one would lose it.

Where the sidebar stands

It already writes identity fields — setIdentityFields in snapshot.ts propagates lifecycle to the identity — but never reads cluster or role for display. Cluster membership is therefore entirely invisible in the UI while already being maintained by it.

  • Core roles lead, fleet follows. kind already distinguishes them: a coordinator is the way into a cluster, a worker is one unit of its work.
  • Open, closed and idle are counted separately on the cluster header, so the memory question is answered without expanding anything.
  • Slots with no session are shown, because an event with no worker is exactly the thing you would want to notice, and it is currently invisible.

Confirmed decisions

1. The toggle MOVES rows. A cluster session appears under CLUSTERS and leaves the flat groups, so every session has exactly one home and the counts elsewhere are honest. The cost is accepted: a coordinator that needs input shows in its cluster rather than in NEEDS YOU.
2. Unfilled slots are rows. An identity with no session is a slot that exists and is not running, which is exactly what you want to notice. It renders as a row like anything else. (As of 2026-07-30 there are none left -- all three were mislinked sessions, now repaired.)
3. Cluster rows behave like every other row. Same complete and archive actions, same open/close, no bespoke cluster verbs. The only additions are a role colour on rows that have a role, and a shelvable header. Nothing about being in a cluster changes what a session is.
4. Every grouping is shelvable, not just clusters. "Today", "This week", a project, a cluster -- any header can be collapsed. Shelving is a property of grouping itself rather than a feature of one kind of group, so there is one interaction to learn and one place it is implemented.
5. Complete and Archived become ordinary headers, NOT bottom bars. This reverses the sticky-bar decision from the triage plan. With every header collapsible, the original objection disappears: they no longer need pinning to stay reachable, because a collapsed list is short enough to scroll past. They become sections with sessions under them, opened and closed like anything else.

Superseded

Decision 5 of sidebar-triage-ia.html made COMPLETE and ARCHIVED sticky bars pinned to the bottom edge, because sections placed after an infinitely-scrolling list are unreachable. That reasoning held only while every group was permanently expanded. Collapsible headers solve the same problem without a second, differently-shaped affordance at the bottom of the sidebar — and one interaction beats two.

What this does not need

  • No schema change. Everything above is already stored; the sidebar simply does not read it.
  • No new cmux capability. Colour is derived locally, so nothing waits on cmux exposing it.
  • No change to the flat list when the toggle is off. The default view stays what it is today.

Open risk

stage and status_line are the natural source for a per-member status column, and both are empty on every row. Building a status column against them would ship an always-blank column whose emptiness looks like a bug. Either event-watch starts writing them first, or the status column waits.

What changed

  • 2026-07-28 — research complete against the live catalogue; five decisions raised, no implementation started.
  • 2026-07-30 — all five settled. The toggle moves rows, slots are rows, cluster rows keep the ordinary actions, every grouping is shelvable, and Complete/Archived become headers — superseding the sticky bars already built.
  • 2026-07-30 — the three "unfilled slots" turned out to be sessions with identity_key = NULL. Linked via ccs session set --identity; six workers carrying their raw key as a title were retitled. Cluster is now fully linked.
